# gtum Sprint 15 정제 시안 / Sprint 15 Refined Design Baseline

## 사용자 의도 한 문장

`VS Code`처럼 중앙 workbench를 상하좌우로 분할해 코드와 터미널을 함께 쓰고, `conductor`처럼 오른쪽에서 에이전트에게 일을 주고 답을 받으며, 프로젝트 관리는 왼쪽에서 처리하는 작업 환경을 만든다.

## 이번에 고정하는 방향

- 메인은 `분할 가능한 workbench`와 `에이전트 작업창`이다.
- 하단 패널은 기본 기준에서 제거한다.
- 터미널은 여전히 탭 타입이지만, 중앙 workbench 안에서 분할 배치될 수 있어야 한다.
- 좌측은 `VS Code`처럼 접고 펴는 activity bar + side panel 구조이며, 프로젝트 관리도 여기서 맡는다.
- 상단은 프로젝트 탭을 두지 않고, `현재 작업`, `연결 상태`, `활성 에이전트`, `승인 대기` 같은 얇은 상태 헤더만 남긴다.

## 용어 정리

- `Project / Branch / Active File`
  - 전역 상단바의 기본 용어로 쓰지 않는다.
  - `현재 작업`, `연결 상태`, `활성 에이전트`, `승인 대기`처럼 현재 상태 위주로 단순화한다.
  - `브랜치`와 `현재 파일`은 workbench 탭이나 source control view 안에서만 보여준다.
- `Agent Mission Board`
  - `에이전트 작업창`으로 바꾼다.
  - 역할은 `일 주기 + 답변 받기 + 승인 보기`다.
- `Problems / Console / Activity / Notes`
  - 기본 구조에서 제거한다.
  - 필요한 정보는 split pane 안의 탭이나 overlay view로 연다.

## 영역별 역할 재정의

### 1. Top Header

- 보여주는 것
  - `현재 작업`
  - `연결 상태`
  - `활성 에이전트`
  - `승인 대기`
- 하지 않는 것
  - 프로젝트 탭 관리
  - `Branch`, `Active File` 고정 노출

### 2. Left Rail

- 구조
  - `VS Code`처럼 세로 activity bar를 둔다.
  - 아이콘 예시
    - `프로젝트`
    - `탐색기`
    - `검색`
    - `소스`
    - `아웃라인`
  - 클릭 시 side panel이 열리고, 다시 누르면 접힌다.
- 목적
  - 프로젝트 전환과 파일 구조 관리
  - 검색, Git, outline 접근

### 3. Center Workbench

- 기본 상태
  - 처음에는 `빈 작업 공간`이다.
  - `+` 버튼으로 첫 탭을 만든다.
- 탭 모양 규칙
  - 탭은 큰 버튼처럼 보이면 안 된다.
  - `VS Code`처럼 `낮고 가로로 긴 탭`이어야 한다.
  - 즉, 세로 높이는 낮고, 파일명이나 탭 타입을 짧게 읽는 형태가 맞다.
- 탭 생성 방식
  - `코드 탭`
  - `터미널 탭`
  - `Diff 탭`
  - `테스트 탭`
  - `Preview 탭`
- 탭 타입 정의
  - `코드 탭`
    - 실제 파일을 읽고 편집하거나 검토하는 기본 editor 탭
  - `터미널 탭`
    - shell 실행, 로그 확인, 명령 입력을 하는 탭
  - `Diff 탭`
    - 변경된 코드 비교 탭이다.
    - 파일의 이전/이후 비교, patch 비교, 승인 전 변경 검토에 쓴다.
  - `테스트 탭`
    - raw terminal 자체가 아니라 `테스트 결과를 보기 좋게 모은 탭`이다.
    - 실패 테스트 목록, 최근 실행 결과, 재실행 액션 같은 구조화된 결과 view가 맞다.
    - 1차 구현에서는 값이 약하면 생략하고 `터미널 탭` 중심으로 시작해도 된다.
  - `Preview 탭`
    - 렌더링된 결과를 보여주는 탭이다.
    - 예를 들면 `Markdown`, `HTML`, 문서 미리보기, 결과 화면, generated output 확인에 쓴다.
    - 질문하신 해석대로 `md 파일 같은 걸 보여주는 탭`이 맞다.
- 핵심 추가 사항
  - workbench는 `좌우 분할`, `상하 분할`이 가능해야 한다.
  - 예시
    - 왼쪽 `코드`, 오른쪽 `터미널`
    - 위 `코드`, 아래 `테스트`
    - 왼쪽 `코드`, 오른쪽 `Diff`

### 4. Split 동작 규칙

- 활성 탭에서 `Split Right`, `Split Left`, `Split Down`, `Split Up`을 지원한다.
- split 이후 각 pane은 독립적인 탭 스택을 가진다.
- 탭은 pane 간 이동 가능해야 한다.
- pane 닫기 시 남은 pane이 공간을 회수한다.
- 에이전트는 필요한 경우
  - 새 `터미널 탭`을 연다.
  - 기존 탭을 옆 pane으로 분할해 연다.
  - 사용자가 보고 있는 코드 옆에 실행 surface를 붙인다.

즉, 터미널은 여전히 선택형 탭이지만, 선택된 뒤에는 `VS Code`처럼 나란히 두고 볼 수 있어야 한다.

### 5. Right Panel

- 이름
  - `에이전트 작업창`
- 핵심 역할
  - 작업 요청 입력
  - 현재 대화와 응답
  - 승인 대기 항목
  - 어떤 에이전트가 무엇을 맡았는지 확인
- 의도
  - 단순 상태판이 아니라 실제로 `일을 주고 답을 받는 메인 인터랙션 창`이어야 한다.

## 첫 진입 상태 / Empty State

```text
+--------------------------------------------------------------------------------------------------+
| gtum | 현재 작업: 없음 | 연결 상태: 미연결 | 활성 에이전트: 없음 | 승인 대기: 0               |
+--------+----------------------+------------------------------------------+-------------------------+
| 프로젝트 | 프로젝트 목록        |              빈 작업 공간                 | 에이전트 작업창          |
| 탐색기   | 최근 프로젝트        |     프로젝트를 열고 + 버튼으로 탭을 추가하세요 | 연결 후 작업 요청 가능   |
| 검색     |                      |     [ + 코드 탭 ] [ + 터미널 탭 ]         | 최근 응답 / 승인 없음    |
| 소스     |                      |                                          |                         |
| 구조     |                      |                                          |                         |
+--------+----------------------+------------------------------------------+-------------------------+
```

## 작업 중 상태 / Working State

```text
+--------------------------------------------------------------------------------------------------+
| gtum | 현재 작업: 로그인 오류 분석 | 연결 상태: Codex | 활성 에이전트: backend | 승인 대기: 2         |
+--------+----------------------+------------------------------------------+-------------------------+
| 프로젝트 | 파일 / 검색 / Git     | auth.ts | terminal #1 | diff | +         | 에이전트 작업창      |
| 탐색기   |                      +----------------------+-------------------+-------------------------+
| 검색     |                      | ACTIVE CODE EDITOR   | TERMINAL / LOGS   | 작업 요청 입력        |
| 소스     |                      | code + breadcrumbs   | command + output  | 현재 대화 / 답변      |
| 구조     |                      |                      |                   | 승인 대기 항목        |
+--------+----------------------+----------------------+-------------------+-------------------------+
```

## 꼭 버려야 할 요소

- 프로젝트 관리를 담당하는 상단 탭
- 의미 설명 없는 고정 `Code / Diff / Test / Terminal / Preview` 버튼줄
- 하단 고정 패널
- 상태만 잔뜩 보여주는 passive `Mission Board`
- 터미널을 기본 화면 중심에 고정하는 terminal-first 레이아웃

## 지금 기준의 구현 방향

1. 좌측을 `activity bar + collapsible side panel + project management`로 바꾼다.
2. 중앙을 `빈 workbench -> +로 탭 생성 -> 상하좌우 분할` 모델로 바꾼다.
3. 우측을 `에이전트 작업창`으로 바꿔 실제 요청/응답/승인 흐름을 넣는다.
4. 하단 패널은 구현 기준에서 제거한다.
