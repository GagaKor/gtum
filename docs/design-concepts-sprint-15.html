이해 가능한 화면 구조를 먼저 고르는 단계

현재 UI는 기능은 많지만 무엇을 먼저 보고 어떤 흐름으로 움직여야 하는지가 약합니다. 아래 시안은 같은 기능을 서로 다른 서사와 정보 계층으로 재배치한 안입니다.

문제 1

첫 액션보다 상태 카드가 먼저 읽힙니다.

문제 2

`project / code / terminal / agent / debug` 우선순위가 흐립니다.

문제 3

요청과 승인이 무엇을 근거로 이뤄지는지 서사가 약합니다.

선택 기준

`안정적 구현`, `터미널 중심`, `이해 가능성` 중 무엇을 최우선으로 둘지 고릅니다.

권장안

`A. Editor Spine`을 기본으로 하고, `C`의 상단 단계 바를 얹는 혼합형이 가장 현실적입니다.

A

가장 균형형입니다. 코드와 터미널을 중앙의 동급 surface로 두고, 오른쪽은 요청과 승인만 맡습니다.

가장 안전한 구현 VS Code 친화적 editor-like 확장 쉬움
